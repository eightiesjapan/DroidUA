2026-11-03 DroidUA 0.4.0-beta.1 launcher, importer and portable saves
App label is DroidUA (Urban Assault for Android); application ID remains
org.openua.android, debug signing unchanged, versionCode 4. Original cyan/navy
host-station icon generated with built-in image_gen; final PNG is in
app/src/main/res/drawable-nodpi/droidua_icon.png. Prompt and provenance are in
android/artwork/icon-generation.json. StarDroid's installed icon was inspected
as a style reference; its artwork is not included in this repository.

LauncherActivity runs in :launcher, separate from SDL's process, so native Exit
can clean up its process-wide state and return to Play/import/save controls.
The native activity holds engine.lock throughout its lifetime; import/backup/
restore refuse to run while it is active. The existing in-game menu is retained.
About includes eightiesjapan coordination/play-testing, GPT Sol/Astra assistance,
OpenUA/Marisa-Chan/community, original Microsoft/TerraTools credits, controls and
bundled native-library licence texts. This is still a development-signed beta;
public release signing/distribution review remains a later milestone.

Import uses Android ACTION_OPEN_DOCUMENT_TREE for an extracted OpenUA package.
It accepts the package root or a wrapping directory up to two levels above it.
Only known game-data directories and NUCLEUS.INI are copied; Windows EXEs/DLLs
at the package root are ignored. Essential base-game assets/engine resources are
checked. Data is copied into import-stage, before a same-filesystem directory
swap. Existing SAVE/Ghorsave/Taersave, ENV/user.def and android-settings.cfg are
preserved. Original source folder is never modified. Movies are enabled in the
imported configuration; fresh Android settings use Large UI/60 FPS/Touch Auto.
A previous installation is retained in game-previous until the next import;
startup recovers a process death between the two directory renames. Archive
extraction is not built into the game importer; users extract the download first.

Back up saves creates a user-selected ZIP via ACTION_CREATE_DOCUMENT. It contains
SAVE and optional expansion save folders, ENV/user.def and Android display/touch
settings, plus versioned metadata. No maps/music/movies or other game assets.
Restore uses ACTION_OPEN_DOCUMENT, validates archive metadata, paths, duplicate
names, CRCs and size/count limits, then creates a private undo snapshot before
replacing saved progress. A restore-pending marker recovers interruptions before
Play is enabled. Undo last restore is available from the launcher. External
backup ZIPs survive app uninstall; private saves and the undo copy do not.

Diagnostics are local only. DroidUAApplication catches uncaught Java exceptions
including activity/native-library load errors; normal platform exception handling
is preserved. Native main installs a signal-safe fatal summary handler chaining
the existing Android handler, and a bounded rotating SDL log (~1 MB across files).
The launcher worker collects Android ApplicationExitInfo crash/ANR records on
API30+, including native tombstone streams when available, and deduplicates via a
synchronously persisted timestamp. After reopening following a crash, MediaStore
exports Download/DroidUA/DroidUA-report-DATE.zip on API29+ where supported. Older
Android/failed automatic export can use launcher Export diagnostics and a system
file picker. Reports include device/build info, logs, Java/native crash details,
Android-provided trace, display settings and touch layout; not game assets or
saved progress. Nothing is uploaded automatically. A crash before native main on
older Android can have less detail; Android may withhold/expire its system trace.
Internal diagnostic files are files/diagnostics. No storage-wide permission added.
